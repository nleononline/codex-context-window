# Codex Context Window

[English](../../README.md) · Русский

Контекстное окно имеет свойство заканчиваться. Когда Codex сжимает длинный диалог, чтобы освободить место, важные детали, промежуточные результаты, ограничения и незавершенная работа могут потеряться или сохраниться лишь в общих чертах. Из-за этого модель может отклониться от задачи, повторить уже сделанную работу или вообще прийти к неправильному результату.

По умолчанию модель не видит, сколько контекста у нее осталось. Она не знает, что скоро может произойти сжатие, поэтому не может заранее сохранить свое рабочее состояние или скорректировать дальнейшую работу.

Codex Context Window закрывает эту слепую зону. Через хуки жизненного цикла модель получает текущее состояние своего контекстного окна и может учитывать эту информацию в работе. Так она может заранее сохранить важные промежуточные результаты и снизить риск ошибок после сжатия.

Сам плагин не сохраняет и не восстанавливает информацию. Он лишь передает модели короткий сигнал:

```text
<meta>YOUR CONTEXT WINDOW: 193800 / 258400 (75%)</meta>
```

## Установка

Codex Context Window распространяется через маркетплейс плагинов Codex на базе Git. Добавьте маркетплейс и установите плагин через терминал:

```bash
codex plugin marketplace add nleononline/codex-context-window --ref marketplace
codex plugin add codex-context-window@codex-context-window
```

> [!IMPORTANT]
> После установки откройте плагин в Codex Desktop и нажмите **Доверять всем** (`Trust all`) в списке его хуков.

После выдачи доступа откройте новый чат или перезапустите Codex, чтобы хуки плагина загрузились.

### Обновление

Обновите маркетплейс и переустановите плагин:

```bash
codex plugin marketplace upgrade codex-context-window
codex plugin add codex-context-window@codex-context-window
```

## Как это работает

Когда Codex вызывает хук, в его входных данных обычно есть `transcript_path` — путь к файлу текущей сессии. Обработчик читает этот JSONL-файл напрямую. Если поле отсутствует или путь не указывает на файл, он использует `session_id` из тех же входных данных и ищет:

```text
${CODEX_HOME:-~/.codex}/sessions/**/rollout-*-${session_id}.jsonl
```

Резервный вариант используется, только если найден ровно один подходящий файл. Выбранный JSONL-файл читается с конца. Из самой новой записи, где `type == "event_msg"` и `payload.type == "token_count"`, плагин извлекает:

```text
payload.info.last_token_usage.total_tokens
payload.info.model_context_window
```

Если файл сессии или данные о токенах отсутствуют либо недоступны для чтения, хук успешно завершает работу без вывода.

Плагин читает только локальные данные сессии и не выполняет сетевых запросов.

### Покрытие хуков

- `SessionStart`
  - `startup`: `<meta>YOUR SESSION JUST STARTED</meta>`
  - `compact`: `<meta>YOUR CONTEXT WAS JUST COMPACTED</meta>`
  - `clear`: `<meta>YOUR CONTEXT WAS JUST CLEARED</meta>`
- `SubagentStart`: новая сессия субагента только что запущена
- `UserPromptSubmit` и `PostToolUse`: текущая заполненность контекстного окна в видимом модели `additionalContext`

Установите `CODEX_CONTEXT_WINDOW_DEBUG=1` перед запуском Codex, чтобы плагин добавлял название вызванного хука к каждому сигналу и выводил ошибки обработчика в `stderr`:

```text
<meta>YOUR CONTEXT WINDOW: 193800 / 258400 (75%) (hook: UserPromptSubmit)</meta>
```

## Производительность и накладные расходы

Обработчик хуков написан на Rust, чтобы свести накладные расходы к минимуму. В плагин входят готовые самодостаточные бинарники для macOS, Linux и Windows на Arm64 и x86-64. Платформенный лаунчер автоматически выбирает нужный бинарник, поэтому после установки не нужно отдельно устанавливать среду выполнения, инструменты или пакеты.

Обработчик запускается как краткоживущий нативный процесс. Он читает транскрипт с конца блоками по 64 КиБ и останавливается на последнем событии с количеством токенов, поэтому обычно ему не нужно читать или разбирать весь файл сессии.

В эталонном тесте из 500 запусков на macOS с Apple Silicon и активным транскриптом размером 7,8 МБ полный вызов хука занял 9,2 мс по медиане и 12,3 мс на p95, включая POSIX-лаунчер и запуск процесса. Вызов только с сообщением жизненного цикла занял 9,0 мс по медиане, то есть основная часть накладных расходов приходится на запуск процесса. Результаты зависят от платформы, накопителя и нагрузки на систему.

## Совместимость

Плагин читает файлы сессий Codex. Сейчас они хранятся в формате JSONL и имеют префикс `rollout-` в имени. Их внутренняя структура может измениться между версиями Codex. Если ожидаемые данные о токенах станут недоступны, плагин успешно завершит работу и ничего не добавит в контекст модели.
