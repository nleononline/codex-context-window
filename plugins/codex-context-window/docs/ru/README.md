# Codex Context Window

[English](../../README.md) · Русский

Контекстное окно имеет свойство заканчиваться. Когда Codex сжимает длинный диалог, чтобы освободить место, важные детали, промежуточные результаты, ограничения и незавершенная работа могут потеряться или сохраниться лишь в общих чертах. Из-за этого модель может отклониться от задачи, повторить уже сделанную работу или вообще прийти к неправильному результату.

По умолчанию модель не видит, сколько контекста у нее осталось. Она не знает, что скоро может произойти сжатие, поэтому не может заранее сохранить свое рабочее состояние или скорректировать дальнейшую работу.

Codex Context Window закрывает эту слепую зону. Через хуки жизненного цикла модель получает текущее состояние своего контекстного окна и может учитывать эту информацию в работе. Так она может убедиться, что не потеряет важные промежуточные результаты — это может снизить риск ошибок после сжатия.

Сам плагин не сохраняет и не восстанавливает информацию. Он лишь передает модели короткий сигнал:

```text
<meta>ТВОЕ КОНТЕКСТНОЕ ОКНО: 193800 / 258400 (75%)</meta>
```

Codex Context Window рекомендует модели учитывать состояние контекстного окна, чтобы при сжатии не потерялась важная информация, **но не навязывает конкретный способ действий**. Модель сама решает, нужно ли сохранять промежуточное состояние, куда и как его записывать или достаточно подготовить ключевую информацию к сжатию.

По умолчанию начиная с 70% отображаемой заполненности плагин просит модель в дальнейшей работе учитывать риск сжатия и следить, чтобы сжатие не привело к потере информации, необходимой для корректного продолжения работы. При желании вы можете задать поведение в `AGENTS.md` или системных инструкциях Codex: указать, должна ли модель сохранять промежуточную информацию в файлы и, если должна, что именно, куда и как. Без таких инструкций модель выберет способ сама.

## Установка

Codex Context Window распространяется через маркетплейс плагинов Codex на базе Git. Добавьте маркетплейс и установите плагин через терминал:

```bash
codex plugin marketplace add nleononline/codex-context-window --ref marketplace
codex plugin add codex-context-window@codex-context-window
```

> [!IMPORTANT]
> После установки откройте плагин в Codex Desktop и нажмите **Доверять всем** (`Trust all`) в списке его хуков.

После выдачи доступа откройте новый чат или перезапустите Codex, чтобы хуки плагина загрузились.

### Обновление

Обновите маркетплейс и переустановите плагин:

```bash
codex plugin marketplace upgrade codex-context-window
codex plugin add codex-context-window@codex-context-window
```

## Как это работает

Плагин использует хуки жизненного цикла, чтобы передавать модели информацию о контекстном окне в процессе работы.

Обработчик написан на Rust и запускается только на время вызова хука. Он читает файл сессии с конца блоками по 64 КиБ и останавливается на первом подходящем событии, за счет чего не читает файл сессии целиком.

Плагин содержит готовые бинарники для macOS, Linux и Windows на Arm64 и x86-64, поэтому дополнительные зависимости не нужны.

**Все данные читаются локально из текущей сессии, сетевые запросы не выполняются.**

### Покрытие хуков

Ниже приведены точные шаблоны сообщений. Вместо переменных в фигурных скобках подставляются значения из текущей сессии.

- `SessionStart` с источником `startup` срабатывает в начале каждой новой сессии и передает эффективный лимит ее контекстного окна, а `SubagentStart` — лимит нового субагента из его собственного файла сессии. Оба хука передают:

  ```text
  <meta>ЛИМИТ ТВОЕГО КОНТЕКСТНОГО ОКНА — {limit} ТОКЕНОВ. АВТОМАТИЧЕСКОЕ СЖАТИЕ МОЖЕТ ПРОИЗОЙТИ ДО ЕГО ДОСТИЖЕНИЯ. ЕСЛИ ПРИМЕНИМЫЕ ИНСТРУКЦИИ НЕ ЗАДАЮТ ИНОЕ ПОВЕДЕНИЕ, НАЧИНАЯ С 70% ОТОБРАЖАЕМОЙ ЗАПОЛНЕННОСТИ, В ДАЛЬНЕЙШЕЙ РАБОТЕ СЛЕДИ, ЧТОБЫ СЖАТИЕ КОНТЕКСТА НЕ ПРИВЕЛО К ПОТЕРЕ ИНФОРМАЦИИ, НЕОБХОДИМОЙ ДЛЯ КОРРЕКТНОГО ПРОДОЛЖЕНИЯ РАБОТЫ, ВКЛЮЧАЯ КЛЮЧЕВЫЕ ТРЕБОВАНИЯ, ПРИНЯТЫЕ РЕШЕНИЯ, ПРОМЕЖУТОЧНЫЕ РЕЗУЛЬТАТЫ И СОСТОЯНИЕ ЗАДАЧ.</meta>
  ```

- `UserPromptSubmit` и `PostToolUse` передают последнюю доступную информацию о заполненности контекстного окна:

  ```text
  <meta>ТВОЕ КОНТЕКСТНОЕ ОКНО: {used} / {limit} ({percent}%)</meta>
  ```

- `SessionStart` с источником `compact` срабатывает после сжатия. Он сообщает о произошедшем сжатии и повторяет рекомендации, которые могли исчезнуть из предыдущего контекста:

  ```text
  <meta>ТВОЙ КОНТЕКСТ ТОЛЬКО ЧТО БЫЛ СЖАТ. УБЕДИСЬ, ЧТО ВСЯ ИНФОРМАЦИЯ, НЕОБХОДИМАЯ ДЛЯ КОРРЕКТНОГО ПРОДОЛЖЕНИЯ РАБОТЫ, ОСТАЛАСЬ ДОСТУПНА. ЛИМИТ ТВОЕГО КОНТЕКСТНОГО ОКНА — {limit} ТОКЕНОВ. АВТОМАТИЧЕСКОЕ СЖАТИЕ МОЖЕТ ПРОИЗОЙТИ ДО ЕГО ДОСТИЖЕНИЯ. ЕСЛИ ПРИМЕНИМЫЕ ИНСТРУКЦИИ НЕ ЗАДАЮТ ИНОЕ ПОВЕДЕНИЕ, НАЧИНАЯ С 70% ОТОБРАЖАЕМОЙ ЗАПОЛНЕННОСТИ, В ДАЛЬНЕЙШЕЙ РАБОТЕ СЛЕДИ, ЧТОБЫ СЖАТИЕ КОНТЕКСТА НЕ ПРИВЕЛО К ПОТЕРЕ ИНФОРМАЦИИ, НЕОБХОДИМОЙ ДЛЯ КОРРЕКТНОГО ПРОДОЛЖЕНИЯ РАБОТЫ, ВКЛЮЧАЯ КЛЮЧЕВЫЕ ТРЕБОВАНИЯ, ПРИНЯТЫЕ РЕШЕНИЯ, ПРОМЕЖУТОЧНЫЕ РЕЗУЛЬТАТЫ И СОСТОЯНИЕ ЗАДАЧ.</meta>
  ```

### Режим отладки

Установите `CODEX_CONTEXT_WINDOW_DEBUG=1` перед запуском Codex, чтобы увидеть, какой хук создал каждый сигнал:

```text
<meta>ТВОЕ КОНТЕКСТНОЕ ОКНО: 193800 / 258400 (75%) (хук: UserPromptSubmit)</meta>
```

## Производительность и накладные расходы

В тесте из 500 запусков на Apple Silicon с файлом сессии размером 7,8 МБ медианное время полного вызова хука составило 9,2 мс. Большая часть времени пришлась на запуск процесса. Итоговые результаты зависят от вашей системы.

## Совместимость

Плагин читает файлы сессий Codex, формат которых может измениться после обновления приложения. Если плагин не сможет получить из них нужные данные, он просто ничего не добавит в контекст модели и не прервет работу Codex.
